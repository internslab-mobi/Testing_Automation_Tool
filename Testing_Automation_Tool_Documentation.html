Testing Automation Tool (TAT)

Enterprise Quality Assurance, Test Lifecycle Management, and Defect Automation Platform

Java 21 LTS Spring Boot 4.1.1 Spring Cloud Gateway Angular 22 Stateless Dual-Token JWT Apache POI (SXSSF) MySQL 8.x

1. Executive Overview & Key Capabilities

The Testing Automation Tool (TAT) is an enterprise Quality Assurance (QA) and Defect Management ecosystem. It bridges the gap between test case authoring, bulk spreadsheet execution, real-time developer bug resolution, email dispatching, and executive oversight.

Core Mission
Provide software engineering teams with a unified, audited, high-throughput testing platform that enforces structured defect lifecycles, automates communications, and computes quantitative quality health indices.

Key Capabilities

  • Role-Based Access Control (RBAC): Strict boundary enforcement across ADMIN, MANAGER, TESTER, and DEVELOPER.
  • Manager Approval Pipeline: Self-registered users are quarantined with isActive = false until vetted, approved, and assigned an operational role by a Manager.
  • Dynamic Custom Attributes: Custom test case metadata stored via native JSON mapping (@JdbcTypeCode(SqlTypes.JSON)).
  • Bulk Spreadsheet Engine: High-performance Apache POI integration for dynamic template downloads and mass .xlsx test imports.
  • Multi-Tier Execution Tracking: Detailed records of preconditions, test data, steps, UI assertions, and backend database query verifications.
  • Standardized Bug Formatting: Automated defect keys (BUG-<FEATURE_NAME>-001) with state machine validation and full historical change auditing.
  • Real-Time Collaboration: In-context defect comments, multi-format media attachment uploads, and single-click multi-attachment ZIP packaging.
  • Asynchronous Email Alerts: Out-of-band HTML email alerts via Microsoft Outlook / Office 365 SMTP relay with dedicated delivery tracking.
  • Manager Quality Health Index: Mathematical score formulation evaluating test pass percentages against weighted critical and high defect penalties.

4. Security, Authentication & Dual-Token (JWT) Architecture

The platform implements a zero-trust, defense-in-depth security model using stateless Spring Security 6, pure HttpOnly cookies, and Double-Submit CSRF protection.

XSS & CSRF Mitigation Strategy
Sensitive authentication tokens (accessToken, refreshToken) are strictly marked HttpOnly, preventing JavaScript access and neutralizing XSS token theft. Cross-Site Request Forgery is thwarted using Spring Security 6 Double-Submit cookies (XSRF-TOKEN / X-XSRF-TOKEN).

Dual-Token Lifecycle Specification

  • Access Token (accessToken): Lifespan: 15 minutes (900,000 ms). Contains claims: userId, username, role, email, and fullName. Stored in an HttpOnly, SameSite=Lax cookie.
  • Refresh Token (refreshToken): Lifespan: 24 hours (86,400,000 ms). Persisted in MySQL table testing_refresh_tokens and mapped to the user. Submitted via POST /auth/refresh to receive a new access token without prompting credentials.
  • 10-Minute Session Expiry Warning: When refreshed during the final 10 minutes of the 24-hour window, the API returns a structured warning message (sessionExpiryWarning: "Session is expiring soon. Please log in again.").
  • Hard Session Expiration: Once expired or revoked, attempts to refresh fail with HTTP 401 Unauthorized and the message "Refresh token expired. Please log in again.".

In-Memory Email OTP Password Recovery

  1. Request OTP (POST /auth/forgot-password): Validates user email, generates a cryptographically random 6-digit OTP stored in thread-safe memory with a 10-minute TTL, and sends a styled HTML email via notification-service.
  2. Verify OTP (POST /auth/verify-otp): Verifies the OTP without resetting the password.
  3. Reset Password & Seamless Auto-Login (POST /auth/reset-password): Verifies OTP, hashes new password with BCrypt, invalidates all prior refresh tokens, and immediately returns fresh Access and Refresh tokens for instant login.

6. Core Modules Deep-Dive

6.1 User Onboarding & Approval Lifecycle

When new users sign up via POST /auth/register, their accounts are created in a dormant state with isActive = false. Managers inspect pending accounts at GET /manager/users/pending and approve them via PUT /manager/userConfirmation, assigning their operational role. Approval automatically triggers an HTML welcome email.

6.2 Project & Agile Feature Management

Projects represent top-level initiatives mapped to geographical operational regions (e.g. APAC, EMEA, US). Features correspond to Agile sprints and release versions within a project. Files and documentation can be uploaded to projects or features and retrieved individually or bundled into ZIP downloads.

6.3 Test Case Authoring & Bulk Excel Engine

The system supports manual test case creation and bulk spreadsheet imports via Apache POI. Testers download pre-formatted .xlsx templates via GET /testcases/template/{projectId}/{featureId}, populate test cases and execution parameters across 14 standardized columns, and upload via POST /testcases/upload for single-transaction validation and database ingestion.

6.4 Multi-Tier Test Execution Logging

Each test case is paired 1-to-1 with a TestingExecution entity capturing:

  • UI Validations: Text assertions, button visibility checks, DOM status.
  • DB Validations: SQL query confirmations and database state assertions.
  • Execution Status: PASS, FAIL, NO_RUN, BLOCKED, DESCOPE.
  • Automation Feasibility: YES, NO, PLANNED, IN_PROGRESS.

6.5 Defect State Machine & Automated ID Engine

Defects are assigned auto-generated formatted IDs (e.g. BUG-USER_AUTH-001) and strictly follow the state transition workflow:

Enforced Workflow: OPEN ➔ IN_PROGRESS ➔ RESOLVED ➔ FIXED ➔ CLOSED (or REOPENED).
Every update logs historical entries in testing_bug_history and dispatches email notifications to assignees and reporters.

6.6 Defect Collaboration & Media Attachments

Testers and developers communicate through threaded discussions (/bugs/{id}/comments). Screenshots, error logs, and screen recordings can be uploaded and downloaded individually or bundled into ZIP archives.

6.7 Standalone Outlook SMTP Notification Microservice

The notification-service running on port 8091 dispatches asynchronous HTML emails via Microsoft Outlook / Office 365 STARTTLS (port 587). Delivery tracking metadata is persisted in notification_service_db with statuses PENDING, SUBMITTED, and FAILED.

6.8 Streaming QA Summary & Export Microservice

The summary-export-service on port 8092 utilizes Apache POI's SXSSF streaming architecture to export multi-sheet Excel workbooks for entire projects or features without running out of memory on large datasets.

6.9 Manager Quality Health Score Algorithm

Computed dynamically in DashboardServiceImpl:

Pass Rate (%) = (Passed Test Cases / (Passed + Failed)) * 100
Base Score    = (Pass Rate * 0.75) + 25.0
Final Score   = Clamp(Base Score - (Critical Defects * 20.0) - (High Defects * 8.0), 0.0, 100.0)
  • 🟢 EXCELLENT: Score ≥ 85%, Pass Rate ≥ 85%, 0 Critical Defects.
  • 🟡 GOOD: Score ≥ 70%.
  • 🟠 NEEDS_ATTENTION: Score ≥ 50%.
  • 🔴 CRITICAL: Score < 50% OR any open Critical defect.

10. Local Development, Build & Startup Sequence

  1. Ensure MySQL Databases are Active:
    • Interns_db (Primary database)
    • notification_service_db (Notification tracking schema; initialize with notification-service/schema.sql)
  2. Start Notification Microservice (Port 8091): 
    cd D:\Testing_Automation_Tool\notification-service
./mvnw clean spring-boot:run
  3. Build & Start Core Microservices: 
    cd D:\Testing_Automation_Tool\TestingAutomationTool
./mvnw clean package -DskipTests

# Terminal 1: Auth Service (:8081)
cd auth-service && ../mvnw spring-boot:run

# Terminal 2: Main Business Service (:8090)
cd ../main-service && ../mvnw spring-boot:run

# Terminal 3: API Gateway (:8082)
cd ../api-gateway && ../mvnw spring-boot:run
  4. Start Summary Export Service (Port 8092): 
    cd D:\Testing_Automation_Tool\summary-export-service
./mvnw clean spring-boot:run
  5. Start Angular Frontend (Port 4200): 
    cd D:\Testing_Automation_Tool\Testing_Automation_tool_frontend\testing-automation-frontend
npm start
    Navigate your browser to http://localhost:4200.
